# 数学問題を解くためのガイド

## 目的

与えられた数学問題を、方策、シミュレーション、評価・選択、実行、フィードバックの反復に従って解く。未解決問題級の問題を想定し、直接の解法に限らず、解決に間接的に役立つ数学的な方向も検討する。

検討結果と有意義なフィードバックをファイルに残し、次の方策を作る際に参照する。数学的な検討の進め方に加え、シミュレーション、記録方法、評価、フィードバックの作り方も改善対象とする。

## ワークフロー

各工程では、反復の1周で問題解決への進展や新しい情報の獲得など、最大限の効果を得ることを目標とする。その目標にふさわしくないものは棄却・修正する。

### 1. 方策

`problems/README.md` で問題名と対応ファイルを確認し、対象の問題ファイルとそれまでの検討を踏まえて、各ターンで方策候補を4つ作る。対象とする問題ファイルを方策に明示する。関連する複数問題をまとめて扱ってよい。各候補はディレクトリとし、次の4つの方針ファイルをまとめる。

- `simulation_policy.md`
- `evaluation_policy.md`
- `solution_policy.md`
- `feedback_policy.md`

これらは方策工程の出力であり、後続の対応工程で入力として使う。方針の具体的な内容は問題ごとの反復の中で形成する。

前のターンから有効なフィードバックが引き継がれていれば、関係する方針を作成・見直す際に読み、どう生かすか考える。毎回すべての方針を変更する必要はない。

### 2. シミュレーション

`simulation_policy.md` に従って、4つの方策候補それぞれで数学的な検討を進めた場合にどう展開しそうかを予想・短期検討する。

各方策候補のシミュレーションは、複数ファイルに分け、合計1000行程度、1行120文字以内で記録する。

当面は計算機を使わず、自然言語で「こういうことが言えるかもしれない」「この方向は難しそう」「可能性がありそう」といった見通しを検討する。何をどう記録するかもシミュレーション方針に従って選ぶ。

### 3. 評価・選択

`evaluation_policy.md` に従ってシミュレーション結果を評価し、実行する方策候補を選ぶ。

### 4. 実行

選んだ方策の `solution_policy.md` に従って、実際の数学的検討を進める。選んだ方向を検討の中心にして深掘りし、その結果を記録する。

実行では十分な内容を検討し、各ターンの実行記録を複数ファイルに分けて合計10000行程度で記す。各ファイルは1000行程度を上限とする。

実行中にも `evaluation_policy.md` に従って評価する。シミュレーションでの予想と実際の進み方を照らし、検討を続けるか、フィードバックへ進むか判断する。目標達成、行き詰まり、予想からの大きな乖離などを区切りとする。

### 5. フィードバック

`feedback_policy.md` に従って、実行の成果、行き詰まり、予想との乖離を整理し、次のループに有意義なフィードバックを生成・選別する。

各ターンのフィードバックは、合計1000行程度で記録する。

必要な場合に、関係する方針についての学びを残す。毎回すべての要素についてフィードバックを作る必要はない。

フィードバックは独立した記録として保持し、特に有効なものを `feedbacks/README.md` に示す。次のターンでは、この一覧と記録を読み、方策を作る際に参照する。フィードバックを方針ファイルへ直接書き込む工程や、独立した承認工程は設けない。

## 方針ファイルに期待する内容

今後作成する各方針ファイルは、100行程度、1行120文字以内とする。

各方針は、候補ごとのシミュレーションを複数ファイルで合計1000行程度、各ターンのフィードバックを1000行程度とし、実行では十分な内容を検討して複数ファイルで合計10000行程度を記録することを前提に作成する。実行記録の各ファイルは1000行程度を上限とする。論文を参照する際は、`docs/papers/` への記録とその再利用も前提とする。

### 候補間の差別化

各方針ファイルには、その役割に応じて、候補固有の問い・手法・選択基準・停止条件・期待する学びを具体的に記す。
このガイドに記載された共通手順は、各方針ファイルに繰り返し記載しない。

### simulation_policy.md

方策候補に従って検討した場合の展開を、どのように予想・短期検討するかを記す。可能性や難点をどう捉え、何をどう記録するかも扱う。複数ファイルで合計1000行程度、1行120文字以内という規模を前提に、記録内容や形式を反復の中で選択・形成する。

### evaluation_policy.md

シミュレーションをどう評価し、どの候補を実行するか選ぶための方針を記す。実行中の検討結果や予想との乖離を評価し、検討を続けるかフィードバックへ移るか判断するためにも使う。シミュレーションや数学的検討と、それらを評価することは別の役割として扱う。

### solution_policy.md

実行工程で、どのような数学的アイデアや方向を試し、どう深掘りするかを記す。直接の解法に限らず、解決に間接的に役立つ可能性のある方向も扱う。実際の検討結果は、この方針に従って別の記録に残す。

### feedback_policy.md

実行結果から何を学び、次に渡す価値があるかを判断する方針を記す。数学的な検討だけでなく、シミュレーションや記録方法、評価、フィードバックの作り方自体についての学びも対象となる。フィードバックの内容上の種類と、関係する方針は別の軸として扱う。

## ディレクトリ構造と記録

パスは、このガイドを置いた問題ごとの作業ディレクトリを基準とする。記録用ディレクトリは各工程で必要になったときに作る。

```text
AGENTS.md
_tmp/
    turn_001/
        ...
dev_mcp/
    workflow_mcp/
problems/
    README.md
    problem_001.md
    problem_002.md
docs/
    README.md
    papers/
        <論文ごとの記録>/
            ...
policies/
    turn_001/
        policy_001_1/
            simulation_policy.md
            evaluation_policy.md
            solution_policy.md
            feedback_policy.md
        policy_001_2/
            ...
        policy_001_3/
            ...
        policy_001_4/
            ...
simulations/
    turn_001/
        policy_001_1/
            ...
        policy_001_2/
            ...
        policy_001_3/
            ...
        policy_001_4/
            ...
evaluations/
    turn_001/
        ...
executions/
    turn_001/
        ...
feedbacks/
    README.md
    turn_001/
        ...
```

### ターンと方策候補の識別

`turn_001` は第1ターン、`policy_001_1` は第1ターンで生成した1番目の方策候補を表す。ターン番号は3桁で表し、各ターンの候補番号は1から4とする。

### _tmp/

一時ファイルは、現在のターンに対応する `_tmp/turn_001/` のようなディレクトリに置く。`turn_001` は他の記録と同じターン番号を使い、3桁で表す。`_tmp/` 全体をGitの管理対象から除く。

### problems/

問題ごとに `problem_001.md` などのファイルを置き、問題文、与えられた仮定、求める結論、出典があればその出典を記す。各工程の記録から対象の問題ファイルを参照する。結果や途中成果は `problems/` に置かない。`README.md` は問題名と対応する問題ファイルの一覧とする。

### docs/

工程やターンをまたいで参照する共通ドキュメントを置く。定義・記法、参考資料、既知の結果、検討から得た数学的成果や解答を整理する。`README.md` を索引とし、配下の分類とファイル名は内容に応じて選ぶ。

予想と証明済みの結果を区別し、整理した成果から根拠となる資料や検討記録を参照できるようにする。工程ごとの予想、評価、実行の経過、フィードバックは、それぞれの記録用ディレクトリに残す。

### docs/papers/

論文を参照するときは、論文ごとにディレクトリを分け、その内容と関係論文の情報を記録する。書誌情報・参照先、検討に必要な定義・仮定・結果・論証の要点、問題との関係を残し、同じ論文を何度も参照し直す必要がないようにする。以降の検討では、この記録を参照して活用する。

### policies/

方策工程で生成した候補を置く。候補ごとにディレクトリを作り、4つの方針ファイルをまとめる。

### simulations/

シミュレーション工程の予想・短期検討を、ターンと方策候補に対応させて置く。`policies/` と同じ候補識別子を使う。各候補の記録は複数ファイルに分け、合計1000行程度、1行120文字以内とする。

### evaluations/

シミュレーションの評価・選択と、実行中の評価をターンごとに置く。どの方策候補や検討結果を評価したか分かるように記録する。

### executions/

選んだ方策に従って行った数学的検討をターンごとに置く。使った方策と、実際に得た検討結果が分かるように記録する。

### feedbacks/

フィードバックをターンごとに保持する。`README.md` に特に有効なフィードバックとその記録への参照を示し、次のターンへ引き継ぐ。

## Pythonの実行

Pythonを実行する際は `uv run` を使う。余計な環境変数を設定せず、既存の環境・設定で実行する。

## workflow_mcpの役割

`dev_mcp/workflow_mcp/` に置くMCPは、エージェントの権限では実行できない操作を担う。ワークフローの判断と工程進行は、エージェントがこのガイドに従って行う。

フィードバックを却下する場合は、`feedbacks/README.md` の該当参照・要約を整理してから、MCPツール `reject_feedback` の引数 `turn` にターン番号を指定する。対象ターンのフィードバック全体が通常の参照範囲から退避される。
