# 数学問題を解くためのガイド

## 目的

与えられた数学問題を、方策、シミュレーション、評価・選択、実行、フィードバックの反復に従って解く。未解決問題級の問題を想定し、直接の解法に限らず、解決に間接的に役立つ数学的な方向も検討する。

検討結果と有意義なフィードバックをファイルに残し、次の方策を作る際に参照する。数学的な検討の進め方に加え、シミュレーション、記録方法、評価、フィードバックの作り方も改善対象とする。

## ワークフロー

### 1. 方策

問題とそれまでの検討を踏まえ、方策候補を作る。各候補はディレクトリとし、次の4つの方針ファイルをまとめる。

- `simulation_policy.md`
- `evaluation_policy.md`
- `solution_policy.md`
- `feedback_policy.md`

これらは方策工程の出力であり、後続の対応工程で入力として使う。方針の具体的な内容は問題ごとの反復の中で形成する。

前のターンから有効なフィードバックが引き継がれていれば、関係する方針を作成・見直す際に読み、どう生かすか考える。毎回すべての方針を変更する必要はない。

### 2. シミュレーション

`simulation_policy.md` に従って、各方策候補で数学的な検討を進めた場合にどう展開しそうかを予想・短期検討する。

当面は計算機を使わず、自然言語で「こういうことが言えるかもしれない」「この方向は難しそう」「可能性がありそう」といった見通しを検討する。何をどう記録するかもシミュレーション方針に従って選ぶ。

### 3. 評価・選択

`evaluation_policy.md` に従ってシミュレーション結果を評価し、実行する方策候補を選ぶ。

### 4. 実行

選んだ方策の `solution_policy.md` に従って、実際の数学的検討を進める。選んだ方向を検討の中心にして深掘りし、その結果を記録する。

実行中にも `evaluation_policy.md` に従って評価する。シミュレーションでの予想と実際の進み方を照らし、検討を続けるか、フィードバックへ進むか判断する。目標達成、行き詰まり、予想からの大きな乖離などを区切りとする。

### 5. フィードバック

`feedback_policy.md` に従って、実行の成果、行き詰まり、予想との乖離を整理し、次のループに有意義なフィードバックを生成・選別する。

必要な場合に、関係する方針についての学びを残す。毎回すべての要素についてフィードバックを作る必要はない。

フィードバックは独立した記録として保持し、特に有効なものを `feedbacks/README.md` に示す。次のターンでは、この一覧と記録を読み、方策を作る際に参照する。フィードバックを方針ファイルへ直接書き込む工程や、独立した承認工程は設けない。

## 方針ファイルに期待する内容

### simulation_policy.md

方策候補に従って検討した場合の展開を、どのように予想・短期検討するかを記す。可能性や難点をどう捉え、何をどう記録するかも扱う。記録の形式やファイル粒度は、反復の中で選択・形成する。

### evaluation_policy.md

シミュレーションをどう評価し、どの候補を実行するか選ぶための方針を記す。実行中の検討結果や予想との乖離を評価し、検討を続けるかフィードバックへ移るか判断するためにも使う。シミュレーションや数学的検討と、それらを評価することは別の役割として扱う。

### solution_policy.md

実行工程で、どのような数学的アイデアや方向を試し、どう深掘りするかを記す。直接の解法に限らず、解決に間接的に役立つ可能性のある方向も扱う。実際の検討結果は、この方針に従って別の記録に残す。

### feedback_policy.md

実行結果から何を学び、次に渡す価値があるかを判断する方針を記す。数学的な検討だけでなく、シミュレーションや記録方法、評価、フィードバックの作り方自体についての学びも対象となる。フィードバックの内容上の種類と、関係する方針は別の軸として扱う。

## ディレクトリ構造と記録

パスは、このガイドを置いた問題ごとの作業ディレクトリを基準とする。記録用ディレクトリは各工程で必要になったときに作る。

```text
AGENTS.md
dev_mcp/
    workflow_mcp/
policies/
    turn_001/
        policy_001_1/
            simulation_policy.md
            evaluation_policy.md
            solution_policy.md
            feedback_policy.md
        policy_001_2/
            ...
simulations/
    turn_001/
        policy_001_1/
            ...
        policy_001_2/
            ...
evaluations/
    turn_001/
        ...
executions/
    turn_001/
        ...
feedbacks/
    README.md
    turn_001/
        ...
```

### ターンと方策候補の識別

`turn_001` は第1ターン、`policy_001_1` は第1ターンで生成した1番目の方策候補を表す。ターン番号は3桁で表し、候補番号は同じターン内で区別する。

### policies/

方策工程で生成した候補を置く。候補ごとにディレクトリを作り、4つの方針ファイルをまとめる。

### simulations/

シミュレーション工程の予想・短期検討を、ターンと方策候補に対応させて置く。`policies/` と同じ候補識別子を使う。中のファイル数や粒度はシミュレーション方針に従って選び、1つの予想や検討を必ず1ファイルに収めるとは定めない。

### evaluations/

シミュレーションの評価・選択と、実行中の評価をターンごとに置く。どの方策候補や検討結果を評価したか分かるように記録する。

### executions/

選んだ方策に従って行った数学的検討をターンごとに置く。使った方策と、実際に得た検討結果が分かるように記録する。

### feedbacks/

フィードバックをターンごとに保持する。`README.md` に特に有効なフィードバックとその記録への参照を示し、次のターンへ引き継ぐ。

## workflow_mcpの役割

`dev_mcp/workflow_mcp/` に置くMCPは、エージェントの権限では実行できない操作を担う。ワークフローの判断と工程進行は、エージェントがこのガイドに従って行う。

フィードバックを却下する場合は、`feedbacks/README.md` の該当参照・要約を整理してから、MCPツール `reject_feedback` の引数 `turn` にターン番号を指定する。対象ターンのフィードバック全体が通常の参照範囲から退避される。
