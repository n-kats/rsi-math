# workflow_mcp

`templates/dev_mcp/workflow_mcp/` を問題ごとのプロジェクトへコピーして使う。Python 3.12、uv、FastMCPを用い、HTTPで提供する。

## reject_feedback

引数 `turn` に1以上の整数でターン番号を指定する。

対象の `feedbacks/turn_001/` などを、同じプロジェクトの `rejected_feedbacks/turn_001/` へ退避する。対象ターン全体を扱い、ファイル単位の指定はしない。既存の退避先は上書きしない。対象が存在しない場合、不正なターン番号、シンボリックリンクや通常ファイル・ディレクトリ以外の項目がある場合はエラーとする。

退避先へのコピーが完了してから元を除去する。除去に失敗した場合も退避記録は保持する。失敗時は管理者が両方の状態を確認する。処理中は対象ターンを編集しない。

成功時は `status`、`turn`、元の `feedback_path` を返す。フィードバックの採否判断と `feedbacks/README.md` の該当参照・要約の整理はエージェントが行う。

## 実行環境

プロジェクト全体はMCPコンテナへ読み取り専用でマウントし、`feedbacks/`、`rejected_feedbacks/`、uvの保存先だけ書き込み可能にする。

別コンテナのエージェントから `rejected_feedbacks/` が見えないことを実行環境の前提とする。この隔離はエージェント側で設定する。MCP用Composeだけではエージェント側のマウントは変更しない。

公開するツールは `reject_feedback` のみとする。工程進行、評価、README編集、退避済み記録の参照ツールは提供しない。
