# docs

## 目的

`docs/` は、リポジトリの仕様、判断基準、設計、計画、手順、開発途中の差分を記録する場所である。再利用するテンプレート、MCPの実装本体、個別数学問題の成果物は置かない。

## 基本構成

- `アイデア/`: 仕様化する前の着想や候補案。
- `仕様/`: 実現する機能と要件。
- `外部参照/`: 外部資料の参照記録。サイト名ごとのディレクトリに置き、タイトルに日付を付けない。
- `手順/`: 人間向けの作業・運用・確認手順。
- `現状/`: 仕様との差分、未実装、暫定対応、未解決事項、制約。
- `規約/`: 言語、命名、形式、例外方針など。
- `計画/`: 今後の作業順序、依存関係、成果物、完了条件。
- `設計/`: 構成、処理、データ、インターフェースの設計。
- `設計判断/`: 選択理由、トレードオフ、却下した案。

仕様や設計上の判断基準は該当する文書を正とし、実装との差分だけを `現状/` に記録する。ディレクトリや文書が追加・移動したときは `目次.md` も更新する。

## 探し方

`目次.md` でディレクトリと主要文書を確認し、内容に応じて上記の区分から探す。
